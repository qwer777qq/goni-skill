# 고니 AlphaCut 조사와 사용

AlphaCut의 실제 UI를 먼저 확인하고, 관찰한 기능과 공개 정적 코드의 추론을 구분한다. 이 스킬은 고니가 작성한 조사 절차이며 AlphaCut의 내부 코드나 서비스를 소유한다는 뜻이 아니다.

## 시작

1. 대상 URL, 계정에서 접근 가능한 화면, 테스트 입력, 원하는 산출물(기능 목록·템플릿 목록·자막·HTML/CSS·편집 결과)을 확인한다.
2. 현재 프로젝트에 `research/alphacut/REPORT.md`가 있으면 먼저 읽는다. 조사일과 빌드 버전을 확인하고 현재 화면과 달라진 부분만 다시 검사한다.
3. 브라우저 UI의 각 상태를 화면 스냅샷과 렌더링 HTML로 기록한다. 공개 페이지 응답과 로그인 후 DOM은 별도 산출물로 관리한다.
4. 템플릿은 화면에서 보이는 카드 수와 고유 미리보기 수를 함께 세고, 카테고리·문구·미리보기 HTML·폰트·색상·이미지 참조를 인덱싱한다. 공개 JS의 설정 객체를 읽을 때 계산식은 실행된 값으로 단정하지 않는다.
5. 사용자가 제공한 입력으로 생성·편집·자막 내보내기를 시험한다. 생성 시간이나 크레딧 소비, 원본 편집 상태를 기록한다. 템플릿·자막 시험을 원복하려면 저장 상태를 확인한다.
6. 실제 게시나 유료 기능은 해당 작업의 사용자 지시와 계정 권한에 따라 진행한다. 기능이 보이는 것과 실행 검증한 것을 구분한다.

## 재사용할 조사 도구

작업 폴더에 이전 `research/alphacut/`가 있으면 그 안의 `capture_public.py`, `capture_static.py`, `extract_all_presets.py`, `build_template_index.py`를 사용한다. 앞의 두 스크립트는 공개 자산 수집용이고, 뒤의 두 스크립트는 해당 빌드의 정적 코드와 브라우저에서 저장한 카드 DOM이 있어야 실행된다. 새 빌드에서는 추출 코드의 모듈 번호·태그 목록·카드 구조를 재검증한다.

자막은 UI의 TXT/SRT 내보내기를 우선한다. HTML/CSS를 다시 수집할 때는 해시와 원본 URL을 남겨 이후 빌드 변경을 비교한다. 결과 보고에는 템플릿 수, 각 기능을 시험한 범위, 산출물 경로, 미확인 범위를 명시한다.

계정 HTML, 서명된 미디어 URL, 영상 파일, 세션 정보는 공개 저장소에 올리지 않는다. 서버 전용 AI·렌더러 동작은 공개 프런트엔드 코드만으로 확인했다고 표현하지 않는다.

이전 조사에서 확인한 화면 구조와 검증 범위는 [관찰 기준](references/observations.md)을 필요할 때 읽는다.
