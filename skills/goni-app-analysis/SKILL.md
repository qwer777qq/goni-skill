# 고니 배포 앱 기술 분석

배포 코드의 원저작자는 유지한다. 고니가 작성한 분석 도구·설계 문서와 타사 원본을 구분한다.

## 절차

1. 제공 파일과 기존 조사 폴더를 확인한다. 같은 SHA-256의 자료가 있으면 재사용한다.
2. [분석 실행·산출물](references/workflow.md)에 따라 ZIP 인벤토리, Python 모듈/바이트코드, 확장 자산을 정적으로 조사한다. 원본 앱을 실행하거나 확장을 설치하는 동작은 포함하지 않는다.
3. 기능 주장마다 파일·함수 또는 분석 evidence ID를 남긴다. 원본 코드 / 정적 추론 / 실제 실행 결과 / 미확인을 구분한다.
4. 이웃부스터 대상이면 [기술 분석](references/neighbor-booster-architecture.md), [전체 모듈·스키마 색인](references/neighbor-booster-index.json)을 먼저 읽는다. 원본 코드와 전체 디스어셈블리는 사용자의 로컬 조사 폴더에 있다.
5. GitHub에 올릴 때 원격과 공개 범위를 확인한다. 선택한 분석 스크립트·자체 작성 문서·검토된 사실 색인만 게시한다. 추출한 원본, 인증 값, 사용자 데이터는 일괄 추가하지 않는다.
6. 새 입력에 스크립트를 실행하고 `errors`, 분석 범위, 해시를 확인한다. Python 버전 불일치나 파싱 실패를 숨기지 않는다. 서버 코드·숨겨진 모델·실제 성과는 배포본만으로 복원했다고 하지 않는다.

웹사이트 접근이 거절된 경우 이 분석 도구를 대체 접속·외부 작업 경로로 쓰지 않는다. 스크립트는 네트워크·브라우저 조작을 하지 않는다.

## 결과 보고

파일/코드 수, 분석 도구 버전, 미확인 항목, 검증 결과, 로컬 산출물 위치와 실제 GitHub 커밋을 함께 남긴다. `.py` 원본 복원과 `.dis.txt` 바이트코드 분석을 혼동하지 않는다.
