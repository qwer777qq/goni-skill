# 검색 의도를 반영한 제품 리뷰 확장

상품 링크·본인 얼굴 참고·리뷰 스타일 참고를 받아 자연스러운 상세 제품 소개로 확장할 때 사용한다. 기존 배경·소품 교체 테스트와 새 제품 소개의 목적을 구분하고 최신 사용자 요청을 따른다.

## 입력과 근거

- 상품의 정확한 세대·기본칩/상위칩·크기·색상·메모리·저장공간·배열을 선택 옵션으로 확인한다. 상세페이지의 제품군 공통 이미지나 최대 사양을 선택한 상품의 사양으로 가져오지 않는다. 링크의 사용자 제공 제휴 파라미터는 그대로 유지한다.
- 제조사 공식 사양과 대조한다. 촬영 이미지와 선택 색상이 다르면 참조의 역할을 형상/색상으로 나눠 프롬프트에 명시하고 결과에서 확인한다. 추가 옵션 여부, 가격 시각, 조건부 배터리·밝기 수치를 구분한다.
- 사용 가능한 검색 API로 핵심 제품명과 구체적인 구매 질문을 조사한다. 도구명·조회시각·키워드·지역/언어·집계기간·수치를 남긴다. 서로 다른 포털 수치를 합치지 않고, 데이터 없음과 0을 구분한다. 검색량은 고유 인원·구매량이 아니다. API가 금지하는 원천이나 파생 데이터는 사용하지 않는다.
- 검색 결과/공개 질문에서 관찰한 비교 고민을 출처로 남기고, ‘왜 검색하는지’는 기획상 추론으로 표시한다. 예: 기본칩에 메모리를 늘릴지, 상위칩을 살지; 작업 메모리와 원본 저장공간의 차이. 댓글·검색량은 성능 증거가 아니다.

## 구성과 참조

사용자가 중립형을 요청하면 과장된 감탄·무조건 추천·구매 압박을 제외하고 사실, 조건, 사용 절차와 선택 기준으로 대사를 구성한다. 상세 구동 요청은 제품 정지 컷의 확대가 아니라 앱 실행→파일 불러오기→타임라인 조작→미리보기→내보내기 설정처럼 입력과 화면 반응이 연결된 동작으로 구체화한다. 정확한 UI는 권한 있는 실제 화면 녹화를 우선하고, 생성 UI나 다른 운영체제 화면을 해당 기기의 실측 결과로 설명하지 않는다.

질문 → 제품 전체와 손의 조작 → 실제 구조·재질 상세 → 용도별 선택 기준 → 상품 옵션 확인의 흐름으로 구성한다. 사양 나열만으로 끝내지 말고 수치가 어떤 판단에 쓰이는지 설명한다. 직접 측정하지 않은 속도나 배터리를 실측처럼 표현하지 않는다.

사용자가 특정 리뷰어 스타일을 지정하면 도입 질문, 시연, 판단 흐름을 참고한다. 얼굴·목소리는 사용자가 지정한 본인 자료를 사용하며 리뷰어의 정체성을 복제하지 않는다. ‘끝그림’이 스타일을 뜻하는지 실제 마지막 프레임인지 문맥으로 구분한다.

이미지·영상·오디오마다 역할을 구분한다. 본인 참고 속 이전 제품이나 음성의 이전 사양을 새 상품에 섞지 않는다. 새 대사를 만들 때 기존 음성은 음색 참고인지 그대로 유지할 대사인지 명시한다. 모델이 음색·새 대사·입모양을 모두 정확히 처리한다고 가정하지 않는다.

노트북 예: 전체 화면 비율·힌지·노치·키보드·트랙패드·포트·색·금속 반사·접촉 그림자를 고정한다. 작은 제품 글자와 생성 UI는 실측 시연으로 제시하지 않는다. 장면 전환 목적과 카메라 위치를 정하고 얼굴·양손·상품이 잘리지 않는 중간 거리를 기본으로 한다. 정지 사진에 카메라 움직임만 준 결과를 자연스러운 제품 시연으로 판정하지 않는다.

## 크레딧과 완료 판정

현재 사용자가 크레딧 사용을 허용했다면 과거 무료 기본값 때문에 다시 승인을 묻지 않는다. 지정 계정의 실제 잔액, 현재 모델·길이·해상도·표시 비용을 확인하고 합리적 범위의 1건을 접수한다. 구독 구매나 무제한 재생성을 허용받은 것으로 확대하지 않는다. 이전 작업과 신규 작업 ID를 구분한다.

완성 파일의 새 대사/정확한 옵션, 얼굴·턱·입, 손가락·제품 접촉, 힌지·키보드·포트, 화면 원근과 움직임을 실제 결과에서 확인한다. 자동 전사, 정지 표본, 연속 재생·청취의 검증 범위를 구분한다. 치명적 사양 오류나 제품 변형은 통과시키지 않고 해당 구간을 수정한다. 실제 결과에서 썸네일을 만든 뒤 프롬프트·출처·비용·검수 기록과 함께 인계한다.

노션 전체 복사 설치 자료에는 SKILL.md와 모든 참조 파일 본문을 포함한다. 공개 GitHub에는 선택한 스킬 파일만 올리고 개인 얼굴·음성·API 키는 포함하지 않는다. 카페 인계는 검수 상태와 실제 링크를 전달하며 미완성 영상을 성공 사례로 설명하지 않는다.
